# План подключения Apify и OpenRouter

Этот файл фиксирует следующий этап проекта. В текущем шаблоне API-вызовов нет.

## Предлагаемый поток

1. Браузер отправляет URL и выбранную глубину серверному маршруту.
2. Сервер проверяет URL и запрещает небезопасные локальные или служебные адреса.
3. Сервер запускает выбранный Apify Actor с лимитом страниц.
4. После завершения сервер получает элементы из Dataset и удаляет повторы.
5. Компактный набор данных отправляется через OpenRouter в модель с поддержкой структурированного JSON.
6. Сервер проверяет ответ по схеме и возвращает безопасные данные интерфейсу.

## Ожидаемая форма результата

```json
{
  "site": {
    "url": "https://example.com",
    "title": "Example",
    "summary": "Краткое описание сайта"
  },
  "stats": {
    "pages": 12,
    "sections": 3,
    "maxDepth": 3
  },
  "tree": [],
  "observations": []
}
```

## Безопасность

- хранить ключи только в переменных окружения Vercel;
- не отдавать ключи в клиентский код;
- проверять протокол и домен пользовательского URL;
- ограничить число страниц и размер данных для LLM;
- не считать предположение модели подтверждённым фактом;
- показывать понятные ошибки при сбое Apify или OpenRouter.
